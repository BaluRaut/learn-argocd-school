📮 CI/CD pipelines — धडा 03

⏮️ CI/CD च्या आधी

FTP शुक्रवार. एक नेमलेली "deploy व्यक्ती", छापलेली release यादी, मध्यरात्रीची maintenance window, आणि "वेळ मिळाल्यावर" चालवलेल्या tests. Integration महिन्यातून एकदा होई आणि त्याला "integration hell" म्हणण्यामागे कारण होते. CI (2000 चे दशक) ने प्रत्येक push तपासला; CD ने प्रत्येक चांगला build पाठवण्यायोग्य केला.

✅ फायदे

  • प्रत्येक बदल तपासलेला, बांधलेला, आणि शोधता येणारा
  • विसरण्यासारखी माणसाची पावले नाहीत
  • deploy कंटाळवाणे होतात (हेच ध्येय!)

❌ तोटे

  • pipelines म्हणजे तुम्हाला सांभाळावा लागणारा कोड
  • push-शैली: cluster च्या किल्ल्या CI मध्ये राहतात (धडा 04)
  • runs च्या मधे आंधळे — drift दुर्लक्षित राहतो

👍 वापरा जेव्हा

  • प्रामाणिकपणे: जवळपास नेहमी — कोणतीही टीम, कोणताही रेपो
  • किमान: पहिल्या दिवसापासून CI (tests + builds)

👎 दोनदा विचार करा जेव्हा

  • पुढच्या आठवड्यात हटवणार असलेला टाकाऊ prototype
  • …एवढेच. CI सगळीकडे स्वतःची किंमत वसूल करतो.

📖 GitOps — धडा 05

⏮️ GitOps च्या आधी (शब्द 2017 मध्ये तयार झाला)

Ops ज्ञान wiki runbooks, shell इतिहास आणि डोक्यांत राहत असे. Clusters imperatively बदलले जात (हाताने kubectl, CI push), म्हणून "काय चालू आहे?" आणि "कोणी बदलले?" ला विश्वसनीय उत्तर नव्हते — या कोर्सचा भाग 1 म्हणजे नेमक्या त्याच जगाचा संग्रहालय-फेरफटका.

✅ फायदे

  • git = सत्याचा एकमेव स्रोत; audit मोफत
  • drift सतत शोधला आणि परत फिरवला जातो
  • rollback = git revert; DR = रेपो पुन्हा apply
  • बदल कोडसारखे review होतात (PRs)

❌ तोटे

  • सोपस्कार: प्रत्येक बदल git मधून जातो (hotfix ला उशीर)
  • secrets ना जादा यंत्रणा लागते (खाली)
  • "काच फोडा" आणीबाणीला ठरलेली प्रक्रिया लागते
  • टीमसाठी आणखी एक मानसिक मॉडेल

👍 वापरा जेव्हा

  • Kubernetes + एकापेक्षा जास्त env/cluster/टीम
  • compliance/audit चे प्रश्न खरोखर विचारले जातात

👎 दोनदा विचार करा जेव्हा

  • Kubernetes नाही — GitOps साधने k8s-आकाराची आहेत
  • एकट्याचे prototyping जिथे वेग सोपस्कारांपेक्षा महत्त्वाचा

🤖 ArgoCD (साधन) — धडे 06–10

⏮️ ArgoCD च्या आधी (2018, CNCF-पदवीधर 2022)

GitOps स्क्रिप्ट म्हणून अस्तित्वात होते: timer वर kubectl-apply चालवणारे Jenkins jobs, किंवा सुरुवातीचे Flux (दुसरा उत्तम GitOps एजंट — तोच लूप, UI नाही). Spinnaker सारखे जड deploy प्लॅटफॉर्म जास्त करत पण चालवायला ops टीम लागे. ArgoCD ने दृश्य app-tree UI ने मने जिंकली.

✅ फायदे

  • UI: प्रत्येक ॲप, diff, sync स्थिती एका नजरेत
  • app-of-apps + multi-cluster एकाच जागेवरून
  • टीमसाठी SSO/RBAC; प्रचंड समुदाय

❌ तोटे

  • चालवायला, अपग्रेड करायला आणि सुरक्षित ठेवायला आणखी एक controller
  • फक्त k8s — दुसरे काहीही deploy करत नाही
  • चुकीच्या UI परवानग्या git review टाळू शकतात

👍 वापरा जेव्हा

  • अनेक ॲप्स/envs/clusters, माणसांना दृश्यता हवी
  • टीमना RBAC असलेले, self-service deploy हवेत

👎 दोनदा विचार करा जेव्हा

  • एक ॲप, एक cluster → Flux (हलके) किंवा CI push पुरते
  • k8s नसलेली लक्ष्ये (Lambda, VMs) → वेगळी साधने

📚 Helm & Kustomize — धडा 11

⏮️ templating च्या आधी

प्रत्येक environment साठी copy-paste YAML — dev/staging/prod फोल्डर जे एकसारखे सुरू झाले आणि typo-typo ने वेगळे होत गेले (copy-paste drift म्हणजे YAML घातलेला धडा 02 चा रोग). किंवा वाईट: CI मध्ये manifests पुन्हा लिहिणाऱ्या sed स्क्रिप्ट ज्यांचे preview कोणालाच करता येत नसे.

✅ फायदे

  • सत्याचा एक स्रोत + प्रत्येक env साठी छोटे diff
  • envs मधला फरक git मध्ये वाचता येतो
  • ArgoCD दोन्ही थेट render करतो

❌ तोटे

  • Helm templating {{ न वाचता येणारे }} सूप बनू शकते
  • मोठ्या फरकांसाठी Kustomize शब्दबंबाळ होते
  • तुम्ही source नव्हे, render झालेले output debug करता

👍 वापरा जेव्हा

  • एकाच ॲपची 2+ environments (क्लासिक प्रकरण)
  • तृतीय-पक्ष सॉफ्टवेअर install करणे (Helm charts)

👎 दोनदा विचार करा जेव्हा

  • एक env, मूठभर फाइल्स — साधे YAML जिंकते
  • काल्पनिक भविष्यातील envs साठी templating (YAGNI)

🔐 GitOps secrets: Sealed Secrets विरुद्ध External Secrets — धडा 12

⏮️ योग्य GitOps secrets च्या आधी

एकतर secrets git मध्ये चिकटवले जात (कायमचे प्रकाशित — git कधीच विसरत नाही), किंवा ते GitOps च्या पूर्ण बाहेर राहत (हाताने apply केलेल्या Secret फाइल्स ज्या रोबोट सांभाळू शकत नसे — मुद्दाम drift). दोन्ही incident reports मध्ये संपत.

✅ Sealed Secrets चमकतात

  • स्वयंपूर्ण: फक्त एक controller, vault नको
  • encrypted blob रेपोच्या आत राहतो — शुद्ध GitOps
  • सोपे मानसिक मॉडेल (वहीतील कुलूपबंद पेटी)

❌ त्यांच्या मर्यादा

  • rotation = प्रत्येक secret पुन्हा seal आणि पुन्हा commit
  • cluster पुन्हा बांधला = नवी किल्ली = सगळे पुन्हा seal
  • सगळे secrets पाहायला/फिरवायला केंद्रीय जागा नाही

👍 External Secrets चमकतात

  • secrets AWS SM / Vault मध्ये राहतात — rotation अंगभूत
  • एक vault अनेक clusters आणि ॲप्सना सेवा देतो
  • git मध्ये फक्त निरुपद्रवी pointers

❌ त्यांच्या मर्यादा

  • बाह्य साठा + आणखी एक operator यावर अवलंबून
  • vault हे critical infrastructure बनते
  • "सगळे रेपोमध्ये आहे" पेक्षा थोडे कमी

अंगठ्याचा नियम: छोटे/स्वतः होस्ट केलेले → Sealed Secrets · secret manager असलेले क्लाउड → External Secrets. आकृती ↗
